# Web de Brisa Pilates Reformer · Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Web estática de una página para Brisa Pilates Reformer con formulario de reserva (nombre, teléfono, correo) que llega por email.

**Architecture:** HTML + CSS + JS vanilla sin build. `index.html` contiene todas las secciones; `styles.css` lleva los tokens del manual; `main.js` valida y envía el formulario a Web3Forms (o simula el envío si no hay clave). Páginas legales y 404 aparte.

**Tech Stack:** HTML5, CSS (variables), JS vanilla, Google Fonts (Cormorant Garamond + Jost), Web3Forms, OpenStreetMap iframe, fotos de Unsplash.

**Spec:** `C:\Users\elena\brisa-pilates-web\docs\2026-11-17-web-brisa-design.md`
**Manual de marca (fuente de todos los valores visuales y de tono):** `C:\Users\elena\Downloads\manual-de-marca-brisa-pilates.md` — cargar también la skill `anthropic-skills:brisa-pilates-marca`.

### Task 3: Formulario de reserva

**Files:**
- Modify: `index.html` (sección `#reserva`)
- Create: `main.js`

**Interfaces:**
- Form: `<form id="reserva-form" action="https://api.web3forms.com/submit" method="POST" novalidate>` con campos `name="nombre"`, `name="telefono"` (`type="tel"`), `name="email"` (`type="email"`), checkbox `name="privacidad"` con enlace a `privacidad.html`, ocultos `access_key`, `subject` («Nueva reserva de clase de prueba · Brisa»), `from_name` («Web Brisa») y honeypot `botcheck`. Mensaje en `<p id="reserva-mensaje" role="status" aria-live="polite">`.
- `main.js` expone `window.Brisa = { WEB3FORMS_KEY, validateBooking }`:
  - `const WEB3FORMS_KEY = 'PON_AQUI_TU_CLAVE_DE_WEB3FORMS'` (comentario: cómo obtenerla en web3forms.com con tu correo).
  - `validateBooking({nombre, telefono, email, privacidad}) -> { ok: boolean, errors: Array<'nombre'|'telefono'|'email'|'privacidad'> }`. Nombre: ≥2 caracteres sin espacios sobrantes. Teléfono: tras quitar espacios, guiones y `+34`/`0034` inicial, exactamente 9 dígitos. Email: regex `^[^\s@]+@[^\s@]+\.[^\s@]+$`. Privacidad: marcada.

- [ ] **Step 1: Escribir las comprobaciones** (ejecutar en la consola del navegador del panel; deben fallar antes de implementar porque `window.Brisa` no existe):

```js
const v = window.Brisa.validateBooking;
console.assert(v({nombre:'Lucía', telefono:'+34 612 345 678', email:'a@b.es', privacidad:true}).ok === true);
console.assert(v({nombre:'Lucía', telefono:'612345678', email:'a@b.es', privacidad:true}).ok === true);
console.assert(JSON.stringify(v({nombre:'', telefono:'12a', email:'x', privacidad:false}).errors) === '["nombre","telefono","email","privacidad"]');
console.assert(v({nombre:'Lucía', telefono:'61234', email:'a@b.es', privacidad:true}).errors[0] === 'telefono');
```

- [ ] **Step 2:** Ejecutarlas → fallan con «Cannot read properties of undefined».
- [ ] **Step 3: Implementar `main.js`:** `validateBooking`; al enviar: validar → si hay errores, marcar `aria-invalid="true"` en cada campo, mostrar el error exacto del manual y enfocar el primer campo erróneo; si es válido, deshabilitar el botón («Enviando…») y:
  - si `WEB3FORMS_KEY` es el texto de ejemplo → no hacer fetch, `console.info` avisando del modo demo, mostrar la confirmación exacta y resetear el formulario;
  - si no → `fetch` POST JSON a `https://api.web3forms.com/submit`; respuesta `success: true` → confirmación + reset; si falla o hay error de red → mensaje de error, conservar los datos.
  - Siempre reactivar el botón al terminar. Además, el script de revelado (`IntersectionObserver` que añade `.is-visible` a `.reveal`), que no hace nada si hay reduced motion.
